## 1. 结论先行

**四位评审一致认为报告"部分成立"（partially holds）。**

| 评审 | 立场 | 最终裁决 | 置信度 |
|---|---|---|---|
| C1（Codex） | 辩护方 | 部分成立 | 94% |
| C2（Codex） | 质疑方 | 部分成立 | 96% |
| O1（Opus） | 辩护方 | 部分成立 | 88% |
| O2（Opus） | 质疑方 | 部分成立 | 85% |

一句话概括：
- **成立的部分**：BFM-Zero 能对接触变化做出反应，部署时的 actor 没有任何显式的接触输入、输出或规划。
- **不成立的部分**：报告的核心论断是"接触是必要的隐变量，BFM-Zero 已在隐式估计接触"。这个论断的推理链条无效，对这个具体网络来说也尚未经过检验。
- **提出的扩展**：显式接触信念估计器（先只做足底受力接触和打滑）**在仿真中可行**。"感知 → 接触规划器 → BFM"三层架构目前**证据不足**，关键瓶颈是"接触意图 → `z`"这个接口，报告完全没有定义它。

## 2. 报告主张了什么

1. BFM-Zero 部署时的 actor 只看本体感觉（关节位置和速度、角速度、重力投影）加最近 4 帧的历史和动作，没有接触或力的信号。接触信息只在训练时通过奖励和特权 critic 进入，报告称之为"隐式接触蒸馏"。
2. 理由有四条：接触可以从"动作 → 身体响应"的关系中观测出来；域随机化迫使网络隐式估计动力学和接触；FB 表征要预测正确的占用分布，就必须体现接触；摔倒恢复和防打滑行为也是旁证。
3. 报告把接触能力分为三级：接触反应控制（已证实）、隐式接触估计（很可能存在）、显式接触推理（缺失）。
4. 报告的建议是：用仿真真值训练一个独立的接触信念估计器（每条肢体输出接触、力、打滑、摩擦和置信度），用线性探针检验 BFM 的隐层，在 BFM 之上加一个接触规划器。

## 3. 共识与主要分歧

### 3.1 四方共识

- **命题 1：接触反应控制**。四人都认为这一点已经定性证实。依据是论文 §3.2 和 Fig.7 中被踢、被推、被拉倒后的恢复。但 O1 和 O2 指出，训练时有 30% 概率从躺倒姿态初始化，而且关闭了终止条件，这本身就能解释恢复能力，不能当作"存在估计器"的证据。
- **命题 2：隐式接触估计**。这是报告的核心论断，四人都认为它没有被确立：
  - "actor 特征里含有与接触相关的、对动作有用的信息"属于**有依据的推断**。
  - "存在可解码、并且被因果使用的接触估计"属于**未检验的假设**。
  - "接触是必要隐变量"的论证**无效**。反例是：一个基于 5 帧历史的阻抗式或姿态反馈控制器，不需要识别接触也能做出有用的反应（C1-A5、C2-S2）。
- **FB 论证有误**。代码中 F、B 和两个 critic 都接收 `privileged_state`，只有 actor 是纯本体感觉的（`train.py:649-654`）。在平地上，接触基本可以由特权运动学状态推出来，所以即使 FB 模型完全准确，也不要求 actor 内部有接触变量（O1 首先提出，其余三人认可）。
- **"特权接触信息蒸馏"的说法不准确**。特权状态只包含运动学量：根高度、身体位姿和速度（O2-F1）。`use_contact_in_obs_max` 默认是 False。接触只通过归一化后的辅助惩罚进入训练。
- **报告的两条"核查备注"都已经能由代码回答，结论都对报告有利**：
  - 奖励权重：实际生效的辅助奖励权重是 −1 / −0.4 / −4 / −2，与论文附录一致（`train.py:708-709`）。YAML 里的 scale 只决定启用哪些奖励项，不是实际权重。报告在这一点上读错了文件。
  - `max_local_self`：它被路由进 `privileged_state`，actor 和导出路径都不使用它。
- **命题 3：显式接触推理缺失**。如果"显式"定义为在线策略中有专门的接触估计、约束或规划，那么就已检查的 actor 和导出路径而言，这一条成立。但说"整个系统没有任何显式接触处理"是错的：训练奖励和 §3.3 的自适应目标里都显式计算了接触。
- **输入维度需要更正**：代码中 actor 的非 `z` 输入是 465 维（64 + 29 + 4×93），论文公式 93H+64 在 H=4 时得到 436，两者对不上。观测历史大约覆盖 80 ms，动作历史大约 100 ms。报告写的"8–16 帧对应 100–300 ms"在 50 Hz 下实际应为 160–320 ms。
- **训练覆盖面窄**：
  - 只在平地上训练，没有物体。
  - 推力是通过改基座速度实现的。
  - PD 增益、控制延迟和力矩扰动的随机化都是关闭的。
  - 摩擦随机化范围是 [0.5, 1.25]，质量、摩擦和质心在启动时随机化。因此评估必须按环境划分数据集，不能只按 episode 划分。
- **接触标签质量问题**：仿真器只提供每个刚体的合力 `net_forces_w`，没有接触伙伴、接触点和法向，自碰撞又是开启的，所以膝盖和手部接触的标签不能直接用阈值来做。
- **力和摩擦的可辨识性**：双支撑时，单脚的法向力在没有力矩信息的情况下难以唯一确定。摩擦在没有滑动时最多只能估出一个下界。

## 4. 关键缺陷与风险（按严重程度排序）

1. **把"可能的机制"写成了"已确立的必然"**（四人一致，评审引用了报告第 4、6、16、18、65 行）。报告末尾的"均为假设"免责声明无法抵消正文中"必须""必要"这类断言。建议改写为："BFM-Zero 表现出接触反应行为；隐式接触估计是一个合理且可检验的解释。"
2. **"接触意图 → `z`"接口没有定义**（四人一致）。静态的奖励 `z_r` 无法编码接触的先后顺序，需要 `z` 序列，或者用 tracking 加关键帧。状态 `s` 里没有场景几何，所以"右手扶栏杆 D"这类与环境物体的接触，在零样本下无法表达（O1）。目前唯一公开的先例是 §3.3 中对"无接触/抬脚"这个谓词做 CEM 优化，只覆盖"避免接触"，没有覆盖"主动建立承重接触"。
3. **混淆了 critic 侧和 actor 侧**（O1、C1、C2）。FB 和 critic 的预测再准，也推不出 actor 内部有接触表征。
4. **探针设计有混杂因素**（四人一致）。原始输入、`z`、步态相位，以及"正运动学 + 重力"都能预测接触，所以探针准确率高不代表网络有专门的接触表征。actor 有 `embed_s` 和 `embed_z` 两条分支都接收观测，只擦除其中一条可能会漏掉冗余编码。
5. **真机迁移风险被低估**（O2 主导）。训练时没有做延迟、增益和力矩随机化，代码里关于延迟的唯一依据只是一条"max real delay is 90ms"注释。20–40 ms 的延迟目标没有任何测量支持。膝盖和手部接触在训练中既没有标签也没有惩罚，惩罚项只覆盖骨盆、肩和髋。
6. **估计器的输出没有按可辨识性划定范围**（C1 主导）。接触、力、打滑、摩擦被放在同一个可观测性论断下；要检测膝盖接触，四肢观测器还得扩展；"意外接触"需要有一个计划作为参照。
7. **数字和记录上的错误**：输入维度是 465 而不是 436；历史窗口长度换算有误；对两条核查备注下了错误的或悬而未决的结论。
8. **出处缺口**：真机 checkpoint 和 `deploy` 分支的预处理都没有核实，以上所有关于 actor 的结论都限于公开的 `main` 代码。

## 5. 综合测试方案

评审普遍认为显式估计器和探针研究**可行**，因此给出了测试方案。所有数值门槛都是**事先登记的判定标准**，不是已发表的结果，也不是对结果的预测。

**统一规则**：
- 接触标签只取与地面或物体的接触，排除自碰撞。承重接触定义为法向力 > 5–10 N 并持续 10–20 ms，同时报告 5 N 和 20 N 两档的敏感性。打滑定义为相对接触面的切向速度 > 0.05 m/s。
- 数据集按整条 rollout、动作族、几何和启动时的材质分配来划分，比例 60/20/20。
- 学习类实验至少 3 个种子，探针用 5 个种子。
- 置信区间用 95% 聚类 bootstrap。区间跨过门槛时判为"不确定"。

| 编号 | 实验 | 设置要点 | 主要指标与通过/否决标准 | 基线/对照 |
|---|---|---|---|---|
| T0 | 产物与接口核对（四人都把它列为前置步骤） | 对 checkpoint 和配置做哈希；核对 465 与 436 的维度差异、历史帧的排列顺序和归一化方式；用 10⁴ 个观测比较 Python 与 ONNX 的输出；在半步长下检验标签稳定性 | 动作差 ≤ 1e-4；标签一致率 ≥ 99%；冲量变化 < 5%。任何一项不一致，都会阻塞后续的表征类结论 | 论文记法；导出 wrapper |
| T1 | 原始历史中是否有接触信息 | 每类扰动 ≥ 500 组配对事件，包括撤去支撑、提前触地、地面 ±5/10 cm、摩擦降到 0.3、小腿撞障碍、只改执行器参数 | 从物理触发时刻起 40 ms 内，平衡准确率 ≥ 0.90；仅改执行器参数时误报 ≤ 5%；摩擦未达临界的配对应接近随机（置信区间落在 0.45–0.55）。如果 80 ms 时仍 < 0.80，则否定该扰动类上的可辨识机制（O1） | 只用当前观测；只用观测历史、不含动作；带仪器测量的参照 |
| T2 | 冻结 actor 特征的探针（命题 2b） | 约 200 万步数据；在"实际接触与计划接触不一致"的数据集上，探测 `embed_s`、`embed_z` 和后面几层 | AUROC ≥ 0.90，并且比最强基线高 ≥ 0.05（置信区间 > 0）；前提是只用 `z` 的 AUROC ≤ 0.75。提升量置信区间上界 < 0.02 时，只否定"有可访问性优势"，不能证明表征不存在 | 原始 465 维输入上的线性和 MLP 探针；只用 `z`；正运动学 + 重力启发式；随机初始化的 actor |
| T3 | 因果贡献 | 用 LEACE 擦除或激活替换，秩取 1/4/16，两条分支都做，并做恢复（rescue）对照；每个条件 200 个 episode × 5 个种子 | 恢复成功率下降 ≥ 15 个百分点，并比随机擦除多下降 ≥ 10 个百分点；正常跟踪误差变化 < 5%；rescue 后至少找回 50% 的损失。即使通过，也只能证明这个任务里有因果贡献，不能证明"必要" | 秩和范数匹配的随机子空间擦除 |
| T4 | 独立估计器（仿真） | 因果 TCN，参数 0.5–2M；历史长度 0/20/80/160/320 ms；输入分三档：只用目标、加跟踪误差、加力矩；扩大随机化范围（延迟 0–40 ms、Kp/Kd ±25%、负载 0–5 kg）；Isaac 训练后到 MuJoCo 测试迁移 | 足底接触 F1 ≥ 0.95（名义条件），每个留出类别 ≥ 0.90；打滑 F1 或 AUPRC ≥ 0.80；ECE ≤ 0.05；延迟 p95 ≤ 40 ms；单支撑法向力 MAE ≤ 0.07–0.10 BW；跨仿真器 F1 下降 ≤ 5 个百分点 | 正运动学启发式；原始历史 MLP；冻结 actor 上加接触头；动力学残差观测器 |
| T5 | 用真值接触测试"接触 → `z`"接口（冻结 BFM） | Tier A：平地落脚点、重心转移、跪地、手撑地起身。Tier B：5/10 cm 台阶、手撑墙 20–50 N 持续 ≥ 1 s。接口三种：关键帧转 tracking `z`、接触谓词奖励转 `z_r`、CEM 或双重退火搜索 `z` 序列。预算固定为 2048×6，另做一次 4× 复测。每个任务族 100 个任务 × 5 个种子 | 通过线：有序完成率 ≥ 80–90%，位置误差 ≤ 5 cm，时序误差 ≤ 100 ms，摔倒 ≤ 2–5%。在 4× 预算下完成率仍 < 50%，而参照控制器 ≥ 90% 时，否定该接口在这一预算下的可行性，但不能证明不存在可行的 `z`。在线运行要求单次更新 p95 ≤ 100 ms | 最近邻动作片段的 `z`；同预算随机搜索；专门训练的 PPO 或全身控制器（用来证明任务物理上可行） |
| T6 | 真机时序预算 | 用仪器锤敲击小腿和脚；力板、IMU、编码器与策略日志同步，同步误差 ≤ 2 ms | 分别测管线延迟 d_p 和估计器延迟 d_e。端到端 p95 ≤ 40 ms 用来检验报告的说法；端到端 ≤ 60 ms 且 d_e ≤ 40 ms 为可用门槛；推理 p99 ≤ 5 ms | 无（纯测量） |
| T7 | G1 分阶段真机试验（估计器先只在旁路观测，不参与控制） | 依次进行：吊架上踏步、自由行走、三档推力、μ≈0.3 的垫子、跪地；手撑墙只有在 T5 tier B 通过后才做。每个条件 ≥ 30 次 × 3 个 session，留出 1 个 session | 足底 F1 ≥ 0.90，打滑 ≥ 0.70–0.80，端到端 p95 ≤ 60 ms，仿真到真机 F1 下降 ≤ 0.10。足底 F1 < 0.80 或 p95 > 80 ms 时，否定"用作反应触发器"的用途 | 不改动的 BFM；通用残差触发器 |
| T8 | 重训归因实验（单独立预算） | 历史长度 H ∈ {0, 4}，奖励分为：完整奖励、去掉打滑奖励、去掉全部接触门控项、时间平移门控、不门控的脚速惩罚；每组 3 个种子；在默认随机化和扩大随机化下都评估 | H=4 的恢复率比 H=0 高 ≥ 20 个百分点，说明历史有用（不等于证明了接触推理）。完整奖励比平移门控的打滑距离少 ≥ 20%，并且恢复率高 ≥ 10 个百分点，说明接触门控有贡献。只在默认随机化下得到零结果时判为"不确定"（O1 依据论文 App. F.2 提出：奖励效果在仿真中难以观察，主要体现在真机上） | 官方 checkpoint 出处不明，不作为对照 |

**建议执行顺序**：T0 → T1 → T2/T3（与 T4 并行）→ T5 → T6 → T7。T8 单独立项。
